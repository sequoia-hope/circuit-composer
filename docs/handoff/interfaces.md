# interfaces → boardroom crates/interfaces

Typed interfaces and power contracts: the data model the pin solver and the supply rule match
on, plus the checker that says where that data disagrees with itself. Interface **types**
(`library/interfaces.json`: `i2c`, `spi`, `uart`, `pwm`, `logic`, `analog`, `pio`, `usb`, `swd`,
`qspi`) are bundles of signals named from the device's side, with roles and joins. Each package's
`ports.json` declares **instances** of them (fixed pins, per-variant pins, or through the
package's **mux table**) and, on its pin functions, cited **power contracts** (`power_in`,
`power_out`; `src/power.rs`). Size: 726 lines of `src` (lib 414, power 312, unit tests
included), no `tests/` folder. Depends on `serde`, `serde_json` only. Used by `pinsolve`,
`ccomp` (`library check`, `interfaces`, `recipe` checks) and `app/core` (types from JSON).

## Model in five minutes

`src/lib.rs`:
- `Types` (:27) / `Type` (:34): `roles`, `bus`, `signals` (name → `SignalSpec { dir, drive }`,
  direction as the controller sees it), `optional`, `per_target` (SPI's CS), `joins` (which
  signal meets which: SDO↔SDI), `rules` (free JSON the pin solver's interface rules read: today
  `i2c.rules.pullup` with SLVA689A's modes).
- `Interface` (:71), one instance in a package: `type`, `roles`, `signals` (own name → type
  name, e.g. the RP2350's `TX` is `SDO`), `pins` (signal → pin name), `pins_by_variant`, `mux`
  (reached through the mux table), `per_pin` (each pin its own one-signal interface: SIO, ADC),
  `implements` (PIO can be i2c, spi…), `excludes`, `dir`, `drive`, `citation`, and flattened
  `extra` (`addresses`, `max_khz`, `requires`).
- `Mux` (:117): GPIO name → list of `[function, instance, signal]` (`["F3", "I2C0", "SDA"]`).
  The RP2350's is generated by `tools/rp2350_mux.py` from datasheet Table 3.
- `Ports` (:141) is the subset of `ports.json` this crate reads: `functions` (raw JSON per pin
  function: kind, levels, power, nominal_v…), `variants` (variant → pin number → `{name,
  function}`), `interfaces`, `mux`.
- `Ports::find` (:164): a variant's pins called `name` or `name_…` (`GPIO26` finds
  `GPIO26_ADC0`). `Ports::options(variant, iface)` (:171): each of an instance's own signals →
  `Vec<PinChoice { number, name, function }>`, from fixed pins and the mux, sorted by pin number.
  A signal with no entry cannot be placed on that variant (PWM9 on a QFN-60).
- `check(types, package, ports, sources)` (:225): unknown type/role/signal/implements/excludes/
  variant, `per_pin` on a multi-signal type, citation source not in the package's
  `sources/sources.json`, mux-reached interface the mux never names, an interface with no pins,
  fixed pins missing on a variant, a required signal no pin carries on a variant, mux GPIOs no
  variant has; then `power::check`. `check_all(root)` (:324) runs it over
  `root/library/interfaces.json` and every `root/packages/*/ports.json`, plus type-level checks
  (optional/per_target/joins naming real signals). `Report { ok, types, packages, mux_pins,
  errors }`.

`src/power.rs` (spec "Supply selection", item 1; bc32646):
- `PowerIn` (:29): `v` [min, max] (0 allowed as min: no minimum), `draw_a` `{typ, max, when,
  citation?}`, `citation`. `deny_unknown_fields`.
- `PowerOut` (:55): `from` (the `power_in` function feeding it; empty for `source`), `port`
  (when the package circuit makes the output, e.g. a buck past its inductor), `topology` (one of
  `TOPOLOGIES`, :25: ldo, buck, boost, buck_boost, charger, switch, diode, source), `v_out`,
  `i_max_a`, `dropout_v {max, at_a}`, `r_on_ohm`, `off_below_v`, `efficiency {value, at_a, vin,
  citation?}`, `iq_a`, `theta_ja_c_per_w` + `tj_max_c`, `enable {function, on_when_open, tie}`,
  `also` (further `switch`/`diode` paths into the same output: a load-sharing VSYS), `citation`.
  `paths()` (:108) splits `also` into separate outputs.
- `of(function)` (:158) parses a function's `power` by its `kind`. `check(functions, sources)`
  (:178): ranges, non-negative draws, typ ≤ max, topology known, `from` is a contracted
  `power_in`, a ldo/buck/switch/diode/charger says how it behaves below regulation, an ldo gives
  `dropout_v`, efficiency in (0, 1], `also` paths only switch/diode with a drop figure, θJA and
  Tj together, `enable` names real functions, every citation's source known.

Data: `library/interfaces.json` (types), `packages/*/ports.json`,
`packages/*/sources/sources.json` (keys only). 25 power contracts on 11 packages at bc32646; the
TLV62569's `VOUT` and lipo_load_share's ports added in 0def710. usblc6 has none on purpose (a
TVS's working voltage is not a supply range).

Invariants: `options` output order is stable (pin number, then string) because the pin solver's
tie-break and its tests depend on it; `check_all` must pass on the repo's data (a test asserts
it); contract structs deny unknown fields, so a typo in `ports.json` is an error, not ignored.

## Solid

- `tests::this_repositorys_interfaces_check`: `check_all` on the real `library/` and `packages/`
  passes; the RP2350 mux has 48 GPIOs.
- `tests::i2c0_reaches_every_fourth_gpio_and_more_on_the_qfn80`: I2C0 SDA on GPIO0,4,…,28 at F3
  on the RP2350A; 12 SCL pins on the RP2350B; PWM9 only on the QFN-80; SPI1's TX is SDO.
- `tests::fixed_pins_by_variant`: RP2350 ADC per variant; LSM6DSO I2C on pins 14/13, SPI SDO
  on 1.
- `tests::bad_data_is_named`: missing pin, unknown role, unknown type, uncited source.
- `power::tests::a_regulator_names_its_input_and_how_it_drops_out`: a good NCP730-like contract
  passes; a reversed range, a draw with neither figure, a wrong `from`, an ldo without dropout, an
  unknown source and `power` on a non-power function are each named.
- Exercised end to end by every `pinsolve` test (which reads the real types and ports).

## Known wrong or weak

- **Figures in `ports.json` are cited by `source` + `locator` only, never a quote.** The
  `Citation` here (:111) has no `quote` field, and `tools/library_quotes.py` reads only claim
  files (`library/claims/*.json`, `packages/*/rules.json`). So power contracts and logic levels
  (60 citations on rp2350 alone, 0 quotes in any `ports.json`) are not machine-checked against
  their documents. The working rule "every figure is cited with a quote that library_quotes
  checks" holds for claims, not for these.
- `functions` stays raw `serde_json::Value`; only `power` is typed. Logic `levels` are parsed in
  `pinsolve::levels` from JSON with no schema check here: a misspelled `vih` is silently absent.
- `power_out` functions carry the output voltage twice: `nominal_v` (read by
  `pinsolve::levels`) and `power.v_out` (read by the supply rule). `check` does not compare them.
- A citation is checked only for its source id being known; the locator is free text.
- `check` reports mux-table errors only for GPIOs no variant has; it does not check that a mux
  entry's `instance` is an interface name (a typo makes that function select invisible).
- Clippy (rustc 1.95): `power.rs:152` large size difference between `Power` variants;
  `power.rs:211`, `:228` negated float comparisons (`!(x >= 0.0)`, deliberate to catch NaN).

## Not covered by tests

- `check_all`'s type-level checks (optional/per_target/joins naming unknown signals).
- `check`: `excludes` naming an unknown interface, `pins_by_variant` for an unknown variant,
  `per_pin` on a multi-signal type, a mux-reached interface missing from the mux, an interface
  with no pins, "map it under signals", the mux citation check.
- `power::check`: efficiency out of (0, 1], `also` path rules, θJA without Tj, `enable`/`tie`
  naming unknown functions, a `source` topology, a negative draw, `v_out` for pass elements.
- `PowerOut::paths` directly (used by the supply rule through lipo_load_share).

## Lessons to keep

- Signals are named from the device's own side and joined by the type (`joins`), so the same
  type serves controller and target; a target's direction is the controller's reversed
  (1233468).
- The mux table is generated from the datasheet, never typed by hand: `tools/rp2350_mux.py`
  parses Table 3 with `pdftotext -layout`, telling cells apart by what they name per column;
  `--check` says whether `ports.json` still matches. Hand-typed pin tables were the failure the
  tool replaced.
- A contract gives figures at a stated condition (`draw_a.when`: the RP2350 at 150 MHz, both
  cores) and on the function the datasheet gives them for (the RP2350's core current on
  `VREG_VIN`, not `IOVDD`); a package's draw on a port is the sum over the functions on it.
- What a datasheet does not give is left out and said so, not filled with a typical (bc32646).
  A port with no cited draw takes the recogniser's part-based figure, marked recognised, never
  hard (spec).
- A pass element's `v_out` is only a ceiling (`switch`, `diode` may start at 0), and a
  load-sharing output is several paths (`also`), each judged on its own.

## For the move

- Lands as `crates/interfaces` in the Understanding group, beside `library`. No dependencies to
  rename.
- Tests read `../../library/interfaces.json` and `../../packages/{rp2350,lsm6dso}/ports.json`
  from the crate directory: become the Boardroom root's `library/` and `packages/`.
- `check_all(root)` assumes `root/library` and `root/packages` side by side; keep that layout or
  take two paths.
- `ccomp interfaces PACKAGE [--variant] [--interface]` (`crates/ccomp/src/main.rs:1206`) and the
  interfaces part of `ccomp library check` become `boardroom compose interfaces …` /
  `boardroom library check` (or wherever the library commands go); keep them functions here.
- Differently: add an optional `quote` to `Citation` and extend `library_quotes.py` to
  `ports.json` (and recipes); type `levels` with `deny_unknown_fields`; derive `nominal_v` from
  `power.v_out` or check they agree; check mux entries name real interfaces.
