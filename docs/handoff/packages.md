# packages/ → boardroom packages/

`packages/` holds Composer's chip packages: one folder per chip family, ingested once from its
datasheet (and reference boards where there are any) into cited, machine-readable data that
composition reads instead of the datasheet. 12 packages, 4.5 MB, 163 tracked files (85 of them,
3.6 MB, are rp2350's). The design is the system spec's "Package format" section
(`Circuit Composer — System Spec.md`); what is actually on disk differs from it as noted below.
In Boardroom the spec puts this folder at the root (`packages/`), with the authoring tools under
`packages/tools/`; whether packages get their own repo is open question 2 of
`boardroom/docs/one-system-spec.md` (recommended: stay in Boardroom for now).

## What a package folder holds

| File | Format | Read by |
|---|---|---|
| `manifest.toml` | `[package]` name, `version` (semver), family, license, summary; `[[variants]]` name, package, footprint, per-variant facts, `layouts`; `[sources]` document revisions as text; `[[sourcing]]` role, part, `lcsc`, `checked` date (stock in a trailing comment) | `compose::package_dir` and `pinsolve::supply::candidates`, which read **only** the `version = "…"` line by text scan. Nothing parses the rest. |
| `ports.json` | `note`; `functions` (function name → `kind` [power_in, power_out, ground, signal kinds…], `class`, `supply`, `nominal_v`, `levels` [expressions of `supply`: vih, vil, voh, vol, iol_ma, ioh_ma, iin_ua, vin_max, vin_max_unpowered + when, at_supply_v], `power` [contract, see `interfaces.md`], `note`, `citation {source, locator}`); `variants` (variant → `pins`: number → `{name, function}`); `interfaces` (typed instances, see `interfaces.md`); `mux` (GPIO → `[function, instance, signal]`, rp2350 only) | `interfaces` (types, options, checks), `pinsolve` (levels, solver, supply), `ccomp check package` (pin names across variants) |
| `rules.json` | `package`, `version`, `note`, `claims`: the library's claim records (id, statement, scope, attributes, citation with locator and quote, status, links, `enforced_by`) plus package fields: `requirement` (SI-keyed values), `checks` (part-value checks: `part`, `quantity`, bounds, `when_fitted`), `this_board` (worked values for the circuit), `check` | `library` (as claims), `ccomp check package` (`checks`, layer-scoped metrics), `tools/library_quotes.py` |
| `sources/sources.json` | source id → title, publisher, doc, kind, revision, url or `where`, sha256, bytes, retrieved | `library`, `interfaces::check` (citation ids), `tools/library_fetch.py` |
| `schematic/circuit.VARIANT.json` | `note`, `variant`, `board` (what it was modelled on), `source`, `parts` (role → symbol, value, footprint, `reference_ref`, lcsc, mpn, `near`, `block`, note), `nets` (internal, by role pin `U1.21`), `ports` (`kind` ground/supply/signal, `pins`, note), `chip_pins_unconnected`. The chip is role `U1`. | `compose`, `pinsolve`, `tools/circuit_check.py`, `tools/compose_kicad.py` |
| `schematic/nets.json` | `frame_variant`, `boards`, `nets` (package net → `anchor` pin and `pins`), `differences` | `ccomp check package`, `compose::board_intent` (anchors first). rp2350 only. Generated by `tools/package_nets.py`. |
| `schematic/support.json` | support parts by block, role and board key (`qfn60`, `qfn80`) as fitted on the reference boards | `tools/package_circuit.py`, `package_nets.py`. rp2350 only. |
| `intent.json` | the intent schema (crates/intent) in package names: nets, blocks with roles and placement goals/constraints, domains, regions anchored to parts, sources | `compose::board_intent`, `ccomp check package`, `ccomp compile` (block constraints → regions), `floorplan` |
| `layouts/NAME/` | `layout.json` (generator output: layout, params, estimate, runners_up), `params.json`, `roles.json` (block role → `REF.PAD`), `verify.json` (block, board, measurements, limits, kicad_drc, generator), `fixture.kicad_pcb` + `.kicad_pro` (the test-bench board), `compare.spec.json` + `compare/` (against the vendor reference: check JSONs and SVGs), `block.svg` | `pinsolve::supply` (a `verify.json` present = a verified layout), `verify/tests/package_layouts.rs`, `blockgen/tests/buck.rs`, `compile/tests/regions.rs`, `tools/apply_layout.py`, `lift_layout.py`, `prepare_route.py`, `ccomp floorplan` (rigid blocks) |
| `reference/BOARD/` | `compose.json`, `binding.json`, `check.json`, `measure.spec.json`, `measured.json` for a vendor reference board | `ccomp/tests/compose.rs` (`rp2350a_minimal/compose.json`), `ccomp/tests/package_check.rs` |
| `kicad/` | symbols (and for rp2350 footprints) KiCad lacks | `tools/circuit_check.py` (looked up first), `compose_kicad.py` |
| `README.md` | the package's manual: what was read, every value's reasoning, departures, "Not verified or open" | people |

"Thin" = ports.json (pins, functions, levels, interfaces, power contracts where they apply),
rules.json (9-23 cited claims, part-value `checks`), sources, one circuit, README; enough to
compose and pin-solve, not to check a board against the package or to place a verified layout.
The bolt-earring and motor-controller packages model the chip **as that board wires it**, with
its values and LCSC numbers; where the board departs from the datasheet the claim is `contested`
rather than the value changed.

## How they are validated

- `ccomp library check` (`crates/ccomp/src/main.rs:959`): every `rules.json` as claims
  (`library::Library::check`: ids, statuses, sources, links, both sides of disputes),
  every `ports.json` (`interfaces::check_all`: types, roles, signals, pins per variant, mux,
  power contracts, citation source ids), and the recipes. Passes at 80ac000. A test asserts it
  (`ccomp/tests/library.rs`), and `interfaces` asserts `check_all` itself.
- `ccomp check package BOARD PACKAGE BINDING` (`crates/ccomp/src/package_check.rs`): a **board**
  against a package by role. The binding maps package roles to board designators; package nets
  (`schematic/nets.json`) are found on the board through their pins (passives fitted reversed
  are handled), wiring compared pin by pin, then every block constraint and net length limit in
  `intent.json` is measured on the copper and every `checks` entry in `rules.json` is judged
  against the part's value. Contested claims are soft. Needs `intent.json` and `nets.json`, so
  only rp2350 today. Both RP2350 minimal boards pass every hard check; easy2350 fails one (USB
  over the +3V3 plane).
- `tools/circuit_check.py CIRCUIT.json [--kicad 9|10]`: each circuit against KiCad's libraries
  (package `kicad/` first): symbols and footprints exist, every role pin is a symbol pin and a
  pad, every symbol pin is on a net or listed. All packages pass on KiCad 9 and 10 (f6b47a8,
  b96844e).
- `tools/library_fetch.py` (hashes of every source PDF) and `tools/library_quotes.py` (every
  claim quote found in its PDF). See `research-library.md`.
- Composition tests: rp2350's reference compose (`ccomp/tests/compose.rs`), the battery board
  and bolt earring (`pinsolve/tests`), and every published layout re-measured on its fixture
  (`verify/tests/package_layouts.rs`).

Not validated by anything: `manifest.toml` beyond its version line (variants, layouts lists,
sourcing); that a manifest's `layouts` names folders that exist; logic `levels` keys;
figures in `ports.json` against their documents (they carry locators, never quotes, and
`library_quotes.py` does not read `ports.json`); recipe quotes (also not read by
`library_quotes.py`).

## Known gaps and stale bits

- **Manifests that still name `~/Software/easy_pcb`:** `tlv62569`, `ncp730`, `tps22913`,
  `eg3113`, `ina240`, `lm74700` (each: "Stock is JLCPCB's, from
  ~/Software/easy_pcb/.claude/skills/pcb-design/scripts/jlc_parts.py show"). easy_pcb is moving
  to Boardroom (owner, 2026-11-02); the tool is the pcb-design skill's `jlc_parts.py`, which
  comes in under `skills/`. Other easy_pcb references are records, not paths to follow:
  `rp2350/sources/sources.json` and `rp2350/intent.json` cite "easy_pcb commit 2d56198,
  examples/easy2350/design/parts/rp2350-core.md (not yet on GitHub)"; `usblc6/sources` notes the
  same file sits in easy_pcb's easy2350; `rp2350/kicad/README.md`, `layouts/qfn60-4layer/
  fixture.kicad_pcb` and its `compare/` files mention easy_pcb.
- The spec's `rules.json` "claims scoped to this chip" exists; its `sources/` "links and hashes of
  PDFs, eval boards" is `sources/sources.json` only; `layouts/` "KiCad design block" is a
  generator output plus a fixture board, not a KiCad design block; "stock and price snapshot
  dates" are a `checked` date and a comment.
- No package has a second variant's circuit (rp2350 RP2350B, the motor controller's MCU).
- Versioning is declared, not enforced: compositions pin `name@version` and must match the
  manifest exactly; there is one version per folder, no history of versions, no lockfile.
- Package `rules.json` versions duplicate the manifest's version; nothing checks they agree
  (`ccomp check package` reads the version from `rules.json`).
